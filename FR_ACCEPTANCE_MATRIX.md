# FR-01–FR-21 — матрица реализации и приёмки (v0.24)

**Принцип:** наличие кода и успешный unit-тест ≠ полная приёмка. Этот документ отделяет проверенную локально логику от сценариев, которые требуют работающих PostgreSQL, SQLAdmin, Telegram и MinIO.

Обозначения: **Л** — контракт / логика проверены локально; **E2E** — существует автоматизированный сценарий с PostgreSQL и mock Telegram, не исполненный в этой среде; **В** — необходима внешняя проверка с реальными сервисами. Статус `Л` не равен `принято` по всей системе.

## Проверки в текущем окружении

- `pytest -q`: unit/contract тесты проходят; **два PostgreSQL E2E пропущены**, поскольку Docker отсутствует.
- `alembic upgrade head --sql`: формирование SQL **всех 15 последовательных миграций**; SQL ещё не выполнен на PostgreSQL.
- `python -m compileall -q app`: проверка синтаксиса Python.
- `python -m pip wheel . --no-deps --no-build-isolation -w /tmp/dateideas-wheel`: проверка упаковки при наличии установленных инструментов сборки.

## Внешняя приёмка для статуса «принято»

1. На машине с Docker: `bash scripts/e2e-compose.sh` — изолированная БД `dateideas_test`, миграции и оба E2E, имитация Telegram HTTP без реальных секретов. Все тесты должны завершиться успешно без `skip`.
2. Заполнить секреты **только локально** в `.env`, затем `docker compose up --build -d`. Проверить `/ready`, миграции и logs сервисов, особенно `api`, `dialogue_worker`, `worker`, `callback_worker`, `indexer_worker`.
3. Авторизовать Telethon и выполнить `bash scripts/probe-telegram.sh @kuda_v_moskva 5`. Вручную подтвердить, что реально возвращаются ID, даты, тексты и ссылки. Затем проверить импорт/исправление одной публикации через модерацию.
4. При наличии HTTPS-домена зарегистрировать webhook, проверить `bash scripts/check-telegram-webhook.sh`; отправить запрос в личный чат бота, нажать каждую кнопку, проверить доставку и постоянное исключение после `/new`.
5. В SQLAdmin под учётной записью модератора проверить публикацию/отклонение/исправление/архив, ошибки обязательных полей, и отказ в доступе без авторизации.
6. Проверить MinIO на реальном фото поста (объект сохраняется, выдача только администратору), а также прогноз погоды при реальном запросе на уличный сеанс.

Пока эти шаги не выполнены, **все FR нельзя объявить окончательно принятыми**. Отдельно для выпуска нужны NFR-измерения нагрузки, бэкапы и восстановление, конфигурация доступов и наблюдаемость из спецификации.
