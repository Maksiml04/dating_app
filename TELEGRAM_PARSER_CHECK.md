# Проверка реального чтения Telegram (v0.21)

**Различайте три проверки:** (1) модульные тесты используют подставной Telegram-клиент, (2) публичный предпросмотр канала в браузере проверяет существование публикаций, (3) только `probe` с настоящей Telethon-сессией подтверждает работу MTProto-парсера.

## Первое подключение

В локальном `.env` (не в репозитории) укажите `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`, `TELEGRAM_SESSION=/data/telegram.session`. Получите API ID/HASH в своём Telegram-аккаунте на https://my.telegram.org. Не присылайте API HASH, код подтверждения и файл `.session` в переписку.

После запуска PostgreSQL/миграций и сборки образов:

```sh
# Авторизация один раз, интерактивно: номер, OTP, возможно 2FA
docker compose --profile ingest run --rm telegram_ingest python -m app.telethon_ingest login

# РЕАЛЬНО читаем до 5 публикаций через MTProto, базу не меняем
bash scripts/probe-telegram.sh @kuda_v_moskva 5
# Другой публичный канал:
bash scripts/probe-telegram.sh @kudago 5
```

Успех подтверждают `"connected": true`, ненулевое `posts_received`, `channel_id`, реальные `id`/`date`/`text_preview`/`url`. При ошибке авторизации, недоступном канале, пустом ответе или сетевом сбое команда завершится неуспешно. Первая авторизация может потребовать вступления в закрытые каналы; диагностируйте только каналы, к которым у аккаунта уже есть законный доступ. Команда `probe` не обращается к PostgreSQL и не меняет позицию чтения.

## Импорт в базу

Через административный API или SQLAdmin заведите `telegram_source`, установите `enabled=true`, `username=kuda_v_moskva`, `channel_id` равным **точному `channel_id` из probe** (либо эквиваленту формата `-100...`). Проверка несовпадения ID предотвращает импорт из неправильно указанного канала. Далее:

```sh
docker compose --profile ingest run --rm telegram_ingest python -m app.telethon_ingest sync --limit 100
# Проверка, что сообщения реально сохранены:
docker compose exec db psql -U dateideas -d dateideas -c \
 "SELECT s.username, s.last_message_id, COUNT(m.id) AS saved_posts FROM telegram_source s LEFT JOIN source_message m ON m.source_id=s.id GROUP BY s.id, s.username, s.last_message_id;"
```

В выводе импорта ожидаются `sources`, `fetched`, `saved`, `errors`, по каждому источнику — `checkpoint`. При повторном запуске без новых сообщений `saved` будет 0. Задания не публикуются автоматически, а поступают на модерацию. Новые источники стартуют с **последних** N публикаций, затем читаются все новые сообщения последовательно порциями. Сообщения без текста не создают карточки, но двигают курсор. При ошибке одного источника другие продолжают обрабатываться.

## Ограничения

- Из этой среды без авторизованной Telethon-сессии реальный MTProto-вызов не выполнялся. Тесты FakeClient подтверждают контракт реализации, **не** живое чтение Telegram.
- Импорт одноразовый, не постоянный stream. Его надо запускать по расписанию, если нужен регулярный сбор.
- Сохраняется текст и подпись к медиа, но **не скачиваются фотографии/видео**, сообщения без текста пропускаются.
- Редактирование старых постов и удаление источником пока не синхронизируются.
- При первом запуске читаются только последние N сообщений: это сознательный ограничитель объёма.
- `telegram_source.channel_id` нужно заполнить по `probe`: числовой ID без актуального username может не разрешиться через пустую Telethon-сессию.
- Соблюдайте права на контент, ограничения доступа Telegram и условия использования источников.
