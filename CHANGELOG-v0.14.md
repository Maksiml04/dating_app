# v0.14 — исправление блокирующей ошибки сборки

## Подтверждённая ошибка

`python -m pip install --no-deps --no-build-isolation .` на исходной v0.13 завершался `metadata-generation-failed`: setuptools обнаруживал несколько верхнеуровневых каталогов (`app`, `alembic`, `docs`) и отказывался автоматически собирать пакет. Кроме того, Dockerfile вызывал `pip install .` **до** копирования каталога `app`.

## Исправления

- В `pyproject.toml` указан backend сборки и явное обнаружение пакетов `app*`.
- В Dockerfile каталог `app` копируется до установки проекта.
- Версия пакета обновлена до 0.14.0.
- Добавлены регрессионные тесты на конфигурацию сборки.

## Подтверждено локально

- `python -m pip install --no-deps --no-build-isolation .` — успешно.
- `pytest -q` — 60 тестов успешно.
- Python-модули компилируются.

## Не проверено

- Полная Docker-сборка (Docker недоступен).
- Подключение к PostgreSQL, миграции в реальной БД, работа SQLAdmin и Telegram E2E.
- Зависимости при чистой сетевой установке: локальная проверка установки проводилась с `--no-deps`.

## Следующий блокер

Провести Docker Compose E2E на хосте с Docker и реальной PostgreSQL. Не считать проект production-ready до этого.
