# Изменения v0.11 — извлечение карточек и перепроверка

## Реализовано

1. **Структурированное извлечение из Telegram.** Добавлен `app/catalog_extraction.py`: опциональная OpenAI-совместимая LLM возвращает факты и обязательные буквальные цитаты исходника (`evidence`). Каждое значение проверяется независимо. При отсутствии сервера или ошибке используется прежний эвристический разбор.
2. **Не допускается автоматическая публикация LLM-результата.** Он попадает исключительно в `CatalogDraft` со статусом `needs_review`. Модератор отдельно публикует проверенную карточку через `PublishIn`. Дата без года остаётся только подсказкой.
3. **Потенциальные дубликаты.** Название нормализуется (регистр, `ё/е`, пунктуация), учитывается сходство адреса. Сравниваются только последние опубликованные версии. Система предлагает кандидатов, **не объединяет** объекты автоматически.
4. **Перепроверка срока действия.** Модель `VerificationTask`, миграция `0008_verification_tasks`, планировщик и защищённые API для списка/закрытия задач. После решения `unavailable` последний опубликованный объект архивируется. `verified` не продлевает `valid_until`: для продления модератор должен создать новую версию публикации.
5. **Фоновые процессы.** `draft_worker` готовит черновики из уже одобренных источников, `verification_worker` создаёт задачи перепроверки. Включены в Compose. Для планирования предусмотрено `INSERT .. ON CONFLICT DO NOTHING`.
6. **Сохранение исходного форматирования.** Ingestion теперь сохраняет переносы строк, чтобы заголовок выделялся корректно; хеш сообщения по-прежнему устойчив к различиям в пробелах.

## Как использовать

```bash
cp .env.example .env
# Настройте DATABASE_URL, административные секреты; LLM_* — по желанию.
docker compose up --build -d
# API модератора: /api/admin/drafts, /api/admin/verifications
```

- Сообщение Telegram загружается в `SourceMessage` со статусом `pending_review`.
- Модератор подтверждает его через `/api/admin/source-messages/{id}/review` со значением `approved`.
- `draft_worker` создаёт черновик; данные/дубли просматриваются через `/api/admin/drafts`.
- Модератор самостоятельно вводит подтверждённые сведения для публикации `/api/admin/drafts/{id}/publish`.
- `verification_worker` добавляет просроченные или требующие проверки публикации в очередь.
- Закрытие проверки через `/api/admin/verifications/{id}/resolve` — `verified`, `needs_update` или `unavailable`.

## Ограничения и безопасность

- LLM-поле с подтверждённой буквальной цитатой **не гарантирует**, что факт корректен; нужна человеческая проверка (например, неоднозначная цена «от», цена на человека, устаревшая дата).
- Исторические сообщения, сохранённые до v0.11 без переводов строк, автоматически не восстанавливаются.
- Сравнение дублей остаётся лексико-структурным, не семантическим; не выполняется merge. Даты событий в кандидаты дублей пока не включены.
- Реальное соединение с Telegram/LLM, SQLAdmin и выполнение миграций на PostgreSQL **в этой среде не проверены**: нет PostgreSQL/Docker и части пакетов.
- Все админские API защищены `X-Admin-Key`; отдельного RBAC по операторам пока нет.
- Периодические воркеры не имеют распределённой координации и являются MVP-процессами; `ON CONFLICT` предотвращает создание одинаковых задач перепроверки.
- Для публичного запуска необходимы интеграционные тесты, полноценная FSM, защита данных, rate limits, миграционные проверки и мониторинг.
