# Catalog Service — каталог и публикация

## Модель
`Place` — постоянная локация; `Event` — мероприятие; `Occurrence` — конкретный сеанс; `Offer` — цена/тариф; `Canonical` — единая идентичность объекта; `PublicationVersion` — неизменяемый опубликованный снимок.

## Жизненный цикл
Источник → извлечение → черновик → нормализация → поиск дублей → ручная проверка → публикация → индексация → перепроверка → архивирование/обновление. Изменения черновика не должны незаметно менять уже опубликованный снимок.

## Актуальность
- `last_verified_at` — когда проверены сведения.
- `next_verification_at` — плановая дата повторной проверки.
- `valid_until` — предельное время допустимого показа.
- Время сеанса хранится отдельно от времени публикации и проверки.

Для событий и конкретных сеансов окна проверки строже, чем для постоянных мест. Цена и наличие билетов могут устаревать быстрее адреса. Конкретные сроки остаются на утверждение, а не зашиваются как универсальная константа.

## Объединение дублей
Переадресация алиасов к одному canonical ID, запрет циклов, транзакционное слияние и сохранение истории происхождения. Перед показом всегда разрешается конечный canonical ID.

## Инварианты
Нельзя показывать неопубликованный, архивный, просроченный или отозванный объект. Публикация и постановка задания на индексацию должны фиксироваться атомарно; состояние индекса отслеживается отдельно.
