# Dialogue Service — управление диалогом

## Принцип
Ограниченная Python FSM управляет переходами; LLM только распознаёт намерение, извлекает параметры и формулирует понятные уточнения. Вывод LLM считается недоверенным и проходит проверку схемы.

## Состояния пользовательского диалога
`Idle` — ожидание запроса; `Understanding` — интерпретация; `Clarifying` — уточнение; `AwaitingFeedback` — показаны варианты, ожидается реакция; `Failed` — управляемая ошибка.

## Асинхронный запрос
Отдельно от FSM хранится состояние `queued / processing / completed / failed / cancelled`. При новом сообщении с изменёнными условиями увеличивается `generation_id`. Перед записью результатов, созданием Outbox и отправкой проверяется текущая генерация; старые результаты отменяются или игнорируются.

## Приоритет условий
Текущий явно заданный параметр важнее сохранённого профиля. Жёсткие ограничения не заменяются мягкими предпочтениями. Неоднозначные даты и конфликтующие ограничения требуют уточнения. Число уточнений ограничивается; после предела предлагается управляемый ввод или поиск по известным данным.

## Конкурентность
Обработка одного чата сериализуется, например через блокировку по `chat_id` или очередь с владением чатом. Дедупликация Telegram `update_id` не заменяет защиту от одновременных запросов.

## Отказ LLM
Переход на кнопки/структурированные вопросы и уже валидированные условия; никогда не выдумывать сведения о мероприятиях.
