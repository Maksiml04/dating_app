# Search Service — поиск и ранжирование

## Ответственность
Принимать только валидированный `SearchRequest`, получать пригодные варианты из опубликованного каталога, учитывать время, бюджет, географию, предпочтения и историю показов. Возвращать не более трёх разнообразных `RecommendationCandidate` с объяснимыми причинами выбора.

## Единица рекомендации
`RecommendationCandidate` содержит `canonical_id`, `publication_version_id`, необязательные `occurrence_id` и `offer_id`, проверенные цену и период действия. Нельзя считать один `Event` автоматически доступным во все дни; нельзя отдавать три сеанса одного события как три независимых идеи.

## Конвейер
1. Нормализация пользовательских ограничений Python-кодом. LLM не строит SQL.
2. Проверка жёстких условий: публикация, актуальность, временной интервал, стоимость на двоих, география, исключения.
3. Поиск кандидатов PostgreSQL FTS и pgvector по допустимому множеству; объединение результатов через RRF.
4. Повторное ранжирование по мягким предпочтениям, новизне, истории обратной связи и качеству сведений.
5. Разнообразие по `canonical_id`, категории и характеру активности.
6. Финальная проверка версий и ограничений перед созданием плана отправки.

## Важные правила
- Жёсткое ограничение никогда не ослабляется молча. При конфликте задаётся вопрос или возвращается структурированная причина отсутствия результата.
- Неизвестная цена не считается подходящей под жёсткий бюджет.
- Отсутствие ограничения не равно неизвестному значению поля каталога.
- Время хранится в UTC; выражения «завтра вечером» интерпретируются в локальном часовом поясе пользователя (для московского пилота — `Europe/Moscow`).
- Отсутствие векторного поиска переводит систему в режим FTS-only.
- Сохраняются версии алгоритма, нормализованные условия, список кандидатов и причины отсева.

## Проверка качества
Раздельно измерять полноту извлечения (retrieval recall), точность фильтров, долю запросов с тремя валидными вариантами, разнообразие и пользовательскую обратную связь. Модель эмбеддингов и коэффициенты ранжирования выбираются после офлайн-оценки.
