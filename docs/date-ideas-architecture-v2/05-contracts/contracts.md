# Контракты взаимодействия

## Общие правила
Контракты являются логическими интерфейсами модулей модульного монолита. Все внешние данные валидируются; DTO имеют версии. Нельзя передавать LLM полномочия менять SQL, статусы публикации или права.

## `SearchRequest`
Идентификаторы запроса, пользователя и `generation_id`; временной интервал UTC; бюджет на двоих в копейках; метро/районы/категории; тип помещения; свободные смысловые признаки; исключённые canonical ID. Каждое ограничение различает `hard`, `soft`, `unspecified` и источник (`current_message`, `explicit_profile`, `session_context`).

## `RecommendationCandidate`
`canonical_id`, `publication_version_id`, необязательные `occurrence_id` и `offer_id`, `verified_at`, `valid_until`, проверенная стоимость, признак ограниченности цены и объяснимые `reason_codes`.

## `DeliveryIntent`
`delivery_id`, `request_id`, `generation_id`, `user_id`, сохранённые ID кандидатов, `expires_at`, статус `pending/sending/delivered/ambiguous/failed/cancelled`.

## Ошибки
Различать конфликт ограничений, отсутствие подходящих объектов, устаревшую генерацию, устаревшую публикацию, недоступность зависимости, невалидный ввод и неоднозначную доставку. Ошибка не должна маскироваться пустым успешным результатом.

## Инварианты
Жёсткие условия не ослабляются автоматически; неопределённая цена не проходит бюджет; stale generation не создаёт актуальную выдачу; финальная отправка требует повторной проверки публикации и TTL. Схемы Python приведены в `dto-examples.md`.
