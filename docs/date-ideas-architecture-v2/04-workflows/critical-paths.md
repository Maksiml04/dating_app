# Критические сценарии и сбои

## Входящий запрос
Telegram webhook → проверка → Inbox → сериализация по chat ID → Dialogue → валидация параметров → новая генерация → Search → RecommendationPlan → Outbox → финальная проверка Sender → Telegram.

## Изменение запроса во время поиска
Пользователь меняет бюджет или дату → увеличивается `generation_id` → старые результаты не записываются в активный план и не отправляются. Если отправка уже началась, её результат фиксируется отдельно; новые кнопки относятся только к новой генерации.

## Публикация
Parser создаёт черновик → Catalog нормализует и обнаруживает дубли → администратор проверяет доказательства → транзакционно создаётся `PublicationVersion` и задание индексации → Search использует только пригодную версию. Отзыв публикации немедленно исключает её из финальной проверки.

## Неоднозначная доставка
Если Telegram принял сообщение, но ответ потерян, статус `ambiguous`, а не автоматически `failed`. Политика повторной отправки должна учитывать риск дублей; гарантия exactly-once недостижима только средствами Bot API.

## Деградация
LLM недоступна → структурированные вопросы; pgvector недоступен → FTS-only; устарел каталог → безопасное отсутствие результата; аналитика недоступна → ответ не блокируется. Все переходы наблюдаемы.

## Восстановление
Идемпотентная обработка Inbox, ограниченные повторы фоновых заданий, ручная повторная обработка, проверка резервных копий и журнал причин отказа.
