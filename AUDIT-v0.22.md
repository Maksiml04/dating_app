# Ревизия интеграций MVP v0.21 → v0.22

## Подтверждённые дефекты и исправления

1. **Блокер индексации (исправлено).** `python -m app.indexer` не вызывал `configure_engine()` и при `EMBEDDING_MODEL` падал с `sqlalchemy.exc.UnboundExecutionError`. Проверено воспроизведением на v0.21. В v0.22 CLI инициализирует подключение, а `docker-compose.yml` запускает `indexer_worker` с `--loop`. Нужны реальная модель эмбеддингов (строго 384 измерения) и PostgreSQL.
2. **Атомарность публикации черновика (исправлено).** `catalog.publish()` выполнял `db.commit()` до обновления `CatalogDraft.status` вызывающим API. После сбоя черновик мог остаться непомеченным при уже созданной карточке. В v0.22 публикация делает `flush`, а commit происходит в HTTP-обработчике после изменения статуса черновика. Добавлены тесты границ транзакций.
3. **Нет фактической диагностики webhook (добавлено).** Адрес Telegram webhook конфигурируется ВРУЧНУЮ. Новый `app.webhook_probe` использует read-only `getWebhookInfo`: сравнивает адрес, показывает очередь обновлений, ошибки и `allowed_updates`, не печатает секретный токен. Токен и сеть необходимы для реальной проверки.
4. **Устаревшая документация (исправлено).** Старый README указывал v0.19 как актуальную версию и называл уже написанные модули «не реализованными». Он заменён актуальной сводкой без подмены локальных тестов настоящим E2E.

## Найдено, ещё НЕ исправлено

1. **Кнопки 👍/👎:** `app/dialogue.py` записывает callback-feedback, но `answerCallbackQuery` нигде не вызывается. Telegram-клиент может показывать незавершённое нажатие. Нужен надёжный ответ callback (желательно без сетевого вызова внутри транзакции webhook).
2. **Редактирование постов Telegram:** курсор Telethon читает новые `message_id`, но не обнаруживает правки старых сообщений; исходные цены/даты могут устареть. Нужна отдельная стратегия edit detection/reconciliation.
3. **Данные изображения и MinIO:** сервис MinIO указан в Compose, но `app/` не содержит интеграции сохранения медиа, и сообщения отправляются текстом. Это функциональный пробел, не проблема доступности MinIO.
4. **SQLAdmin:** большинство действий модерации доступны через защищённый API, но кнопки approve/publish/reject непосредственно в веб-панели не завершены.
5. **Полный E2E:** скрипт `scripts/e2e-compose.sh` есть, однако в текущей среде Docker и PostgreSQL недоступны; реальные миграции и Telegram-обмен не подтверждены.
6. **Сетевой вход бота:** API слушает только `127.0.0.1:8000` на хосте. Нужен внешний HTTPS reverse proxy, зарегистрированный Telegram webhook и `TELEGRAM_WEBHOOK_SECRET`. Без этого бот не получит обновления.

## Воспроизводимые проверки

```bash
python -m pip install -e '.[dev]'
pytest -q
alembic upgrade head --sql >/tmp/dateideas-migrations.sql
# Нужен Docker:
bash scripts/e2e-compose.sh
# Нужен реальный BOT_TOKEN в локальном .env, не передавать его в чат:
bash scripts/check-telegram-webhook.sh
# При наличии модели и БД:
docker compose logs indexer_worker --tail 100
```

**Ограничения:** локальные unit-тесты и офлайн SQL Alembic не доказывают работоспособность PostgreSQL, загрузку медиа, сетевую связность Telegram или корректность ответа Telegram на callback.
