# v0.20 — даты в FSM и актуальность сеансов

## Изменения

- `app/date_constraints.py`: распознавание `сегодня`, `завтра`, `послезавтра`, `на выходных`, `в выходные` в фиксированном часовом поясе `MOSCOW_TIMEZONE` (по умолчанию `Europe/Moscow`). Даты преобразуются в абсолютные UTC ISO-строки для JSONB.
- Для текущего дня и выходных начало диапазона не бывает раньше момента сообщения; воскресенье трактуется как текущие выходные.
- `app/dialogue.py`: слова с датами исключены из FTS-запроса, при уточнении дата обновляется без потери темы и бюджета; выражения с отрицанием и неоднозначностью обрабатываются консервативно.
- `app/dialogue_worker.py`: worker не вычисляет относительную дату повторно после полуночи; ответ LLM не может подменить тему отдельной репликой о дате.
- `app/search.py`: прошедшие сеансы исключены из выдачи; ограничение `ends_at` применяется к **времени начала** сеанса по полуоткрытому интервалу, чтобы учитывать мероприятия, заканчивающиеся после полуночи.
- `tests/test_v020_relative_dates.py`: регрессионные проверки, включая границу суток, воскресенье, DST, нормализацию темы, запрос к Occurrence.

## Локальная проверка

Команды:

```bash
pytest -q
python -m compileall -q app alembic tests
alembic upgrade head --sql > /tmp/dateideas-migrations.sql
```

Реальный Docker/PostgreSQL E2E **не выполнен** в данной среде (нет Docker), фактическое применение миграций и SQL-запросов к живой БД не подтверждено. Тесты SQLAdmin в реальном веб-интерфейсе не выполнялись.
