# v0.25 — фото в карточках, операционная готовность, `/liked`

## FR-22: фотографии в пользовательских карточках

- `PublicationVersion.source_message_id` (nullable FK) связывает публикацию с исходным Telegram-постом и его приватным фото в MinIO. Миграция `0016_publication_media`.
- При публикации черновика API автоматически привязывает фото проверенного исходника; модератор уже видел его в приватном превью. Прямая публикация через `PublishIn` принимает `source_message_id` только для одобренного сообщения (ошибка валидации иначе).
- Воркер отправки после **подтверждённой** доставки текста отправляет фото каждого кандидата через `sendPhoto` (multipart: MinIO не доступен из интернета, поэтому Telegram не может скачать объект сам). Подпись — только проверенный заголовок карточки (лимит 1024 символа соблюдается).
- Отправка фото строго best-effort: сбой MinIO или Telegram не меняет статус outbox, счётчиков и факт доставки текста. Фото не отправляются без `TELEGRAM_BOT_TOKEN`.
- `Feedback.created_at` добавлен для хронологии реакций (server_default для существующих строк).

## Операционная готовность

- `GET /metrics` — exposition-формат Prometheus без внешних зависимостей. Счётчики: `webhook_updates_total`, `webhook_rate_limited_total`, `outbox_delivered_total`, `outbox_failed_total`, `outbox_ambiguous_total`, `process_uptime_seconds`. PII (chat_id, тексты) в метриках отсутствуют по контракту и проверяются тестом.
- Rate limiting webhook: скользящее окно на чат (по умолчанию 20/мин, `WEBHOOK_RATE_LIMIT_PER_MINUTE`), превышение — HTTP 429 без обработки. Окно в памяти процесса; для кластера требуется общий счётчик (зафиксировано в docstring).
- `scripts/backup-db.sh` / `scripts/restore-db.sh` — логический бэкап и восстановление PostgreSQL через docker compose с подтверждением.

## Продукт

- Команда `/liked` — последние 10 мест/событий, отмеченных «Подходит», из уже собираемой истории реакций; доступна из `/help`.
